# Как работать над «АВАРИСом» вместе

Игра — статический сайт: HTML + ES-модули + ассеты. Сборки нет, всё, что лежит
в папке, и есть игра. Живёт на https://avaris-game.web.app (Firebase Hosting,
проект `avaris-game`).

## Первый запуск

```bash
git clone https://github.com/Yurrio/avaris-game.git
cd avaris-game
python3 -m http.server 8213 --bind 127.0.0.1
```

Открыть http://127.0.0.1:8213/ — сервер обязателен: игра собрана на ES-модулях,
из `file://` браузер их не загрузит.

Нужен только Python 3 (в macOS и Linux он уже есть). Node.js — лишь для тестов
и вспомогательных скриптов в `tools/`.

## Что где лежит

```
index.html          вся разметка и CSS (в том числе вид курсора)
js/main.js          игровой цикл, камера, управление, HUD, журнал, инвентарь
js/world.js         сборка планеты: рельеф, руины, аномалии, маяки
js/terrain.js       ландшафт, планировка мира, шурфы
js/story.js         чистая логика истории (без three.js) — тексты, знаки, точки
js/mech.js          три механизма (врата, очаг, противовес), пластины
js/rover.js         физика ровера
js/rover-model.js   модель ровера
js/cursors.js       варианты курсора мыши
js/tangut.js        тангутские знаки
js/motes.js         частицы
js/epilogue.js      финальные кадры: анимированные концовки на живой сцене
js/sky-env.js       небо и освещение
js/world-kit.js     вспомогательные модели окружения
js/prop-models.js   модели предметов
assets/             музыка, модели, шрифты, текстуры
vendor/             three.js (r160) — лежит локально, без CDN
tools/              тесты и отладочные страницы (на сайт не выкладываются)
docs/               заметки по проекту
```

## Тесты

```bash
node --test tools/test-story.mjs
```

Ожидаемый результат: **21 проходит, 6 падает** — эти шесть проверяют старый
API (`decodeCorrect`, знак плиты `⧉`) и падают всегда. Это не поломка, регрессией
считать нельзя: важно, чтобы число пройденных не уменьшалось.

## Как вносить правки

Самый простой путь (для небольших изменений):

1. Открыть папку в VS Code, поправить файлы.
2. Панель **Source Control** (⇧⌘G) → написать сообщение → **Commit** → **Commit & Push**.
3. Через минуту сайт обновится сам (см. ниже).

Если правок много или работа идёт параллельно, лучше отдельная ветка:

```bash
git switch -c anna/karta
git add -A && git commit -m "карта: подписи ахолов"
git push -u origin anna/karta
```

Дальше на GitHub — **Pull Request** в `main`. Так видно, что именно изменилось,
и ничего не потеряется.

Перед началом работы и перед пушем полезно подтянуть чужие правки:

```bash
git pull
```

## Как игра попадает на сайт

Автоматически: любой push в `main` запускает GitHub Actions и выкладывает
содержимое репозитория на https://avaris-game.web.app (файл
`.github/workflows/deploy.yml`). Смотреть прогоны — вкладка **Actions**.

Вручную (если есть доступ к Firebase-проекту):

```bash
firebase login
firebase deploy --only hosting
```

Что НЕ выкладывается на сайт (см. `firebase.json` → `ignore`): `tools/`,
`docs/` в служебных целях, `package.json`, `node_modules`, всё скрытое (`.github`,
`.git`). Проверить, что именно уйдёт, можно командой:

```bash
firebase deploy --only hosting --dry-run   # или: firebase hosting:channel:deploy test
```

## Правила, чтобы не сломать друг другу работу

- **Не коммитить секреты**: ключи Firebase, токены, свои пароли — только в личные
  настройки, не в репозиторий.
- **Не переименовывать** `js/main.js`, `index.html` и папку `assets/` — на них
  завязаны пути; если очень нужно, делать отдельным коммитом и предупреждать.
- **Крупные файлы** (модели, музыка) — сначала спросить: репозиторий публичный,
  и лишние 50 МБ останутся в истории навсегда.
- Правки в `index.html` — там же лежит CSS; менять аккуратно, файл большой.
- Ветки с экспериментами не удалять без предупреждения: лучше Pull Request.

## Проверка перед пушем

1. Открыть http://127.0.0.1:8213/ и пройти затронутое место (не только консоль).
2. `node --test tools/test-story.mjs` — прошедших не меньше 21.
3. Если правили ассеты — убедиться, что файлы на месте и пути относительные.
